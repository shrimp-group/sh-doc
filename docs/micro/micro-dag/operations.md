# 编排运营指南

编排工作台（sh-dag-ui）是分布式业务编排引擎 micro-dag 的配套前端，面向编排运营人员提供「流程定义管理」与「实例管理」两大板块。本文从业务操作视角介绍流程设计与发布、实例发起、运行监控与人工干预的完整操作路径。

- 流程定义：把业务处理步骤画成一张「节点 + 连线」的流程图，保存为草稿并发布上线
- 实例：流程按某次入参跑起来的一次运行过程，可全程监控、可人工干预
- 干预治理：对执行中的节点做中断、跳过、重置、重跑等操作，无需重新发起整个实例

### 核心概念速览

| 概念 | 含义 |
|------|------|
| 流程（DAG） | 一张由节点与连线组成的有向流程图，描述业务步骤的先后与分支关系 |
| 节点 | 流程图中的一个处理步骤，每个节点绑定一个 handler（业务处理器） |
| handler | 节点背后的业务动作实现，由业务方在服务端注册；设计器左侧面板即 handler 清单 |
| 连线（边） | 节点间的执行顺序；分支节点引出的连线可附带条件表达式 |
| 版本 | 流程定义的不可变快照，草稿固定为版本 0，发布产生新版本号；实例永远按已发布版本执行 |
| 实例 | 流程按一次入参运行的过程，拥有独立的实例流水号与执行状态 |
| traceCode | 业务跟踪编码，用于把实例与业务单据（如订单号）关联起来 |

## 功能总览

编排工作台包含两个主要页面：

| 页面 | 入口 | 能力 |
|------|------|------|
| **流程定义列表** | 菜单「流程定义」 | 查询流程、新建流程定义、打开设计器、查看历史版本 |
| **实例列表** | 菜单「实例管理」 | 查询实例、发起实例、查看实例详情、终止实例 |

两个页面的查询区均支持「搜索 / 重置」；表格右上角提供列设置，可控制「最新版本」等默认隐藏列的显示。**流程定义列表**的操作列仅提供「设计」「历史版本」两个动作，设计动作通过全屏弹窗内嵌设计器完成；**实例列表**的详情动作通过全屏弹窗内嵌实例详情完成，关闭弹窗后列表会自动刷新。

## 流程设计与发布

### 新建流程定义

1. 进入 **流程定义列表**，点击右上角「新建」按钮，系统打开全屏设计器，标题为「新建流程定义」。
2. 在设计器左上角信息栏填写 **流程名称**（必填，为空时保存会提示「请输入流程名称」）。
3. **流程编码** 无需填写：由系统在后端自动生成，界面只读展示。
4. 编排完成后点击弹窗底部「保存草稿」，保存草稿后即生成该流程的首个草稿（版本 0），列表中出现一条状态为「编辑中」的记录。

### 打开设计器

列表操作列提供「设计」与「历史版本」两个按钮。「历史版本」打开版本历史弹窗，列出该流程的全部版本（版本号列：草稿显示「草稿」，已发布版本显示 vN）、状态与更新时间，点「查看」可打开全屏只读画布，标题为「版本查看 - 流程名称（流程编码 v版本）」。

点击「设计」打开全屏设计器，按流程当前状态分为三种打开方式：

- 有编辑中草稿（状态「编辑中」）：直接打开该草稿继续编辑，标题为「设计流程 - 流程名称（流程编码 编辑中草稿）」。
- 无草稿但有已发布版本：以最新已发布版本为底稿打开设计器，标题为「设计流程 - 流程名称（流程编码 新版本草稿）」，首次「保存草稿」时自动创建新草稿。
- 全新流程：通过「新建」打开，标题为「新建流程定义」（见上节）。

设计器分三个区域：

**左侧 handler 面板（业务节点来源）**

- 列出所有可用的节点处理器（handler）：一个 handler 代表一类业务动作，名称下方显示其编码。
- 顶部提供「搜索 handler」输入框，按名称或编码过滤。
- 系统内置节点（开始 / 结束 / 分支 / 定时器）排列在最上方并带专属配色标识。
- 将 handler 卡片 **拖拽** 到中间画布即可生成节点；同名 handler 重复拖入时，节点编码自动追加序号（如 `demo-delay-1`）。
- handler 按来源分三类：**系统节点**（内置，始终可用）、**业务节点**（业务方注册，日常编排的主力）、**演示节点**（仅当服务端开启演示开关后才会出现在面板中，仅用于学习体验，请勿在正式流程中使用）。

**中间画布（编排区）**

- 拖入的节点可以自由移动位置，坐标实时保存。
- 从节点 **右侧圆点** 按住拖到目标节点 **左侧圆点**（或直接松手落在目标节点上）完成连线，端口有磁吸效果；连线方向仅允许「右出 → 左入」，不允许悬空、自环和重复连线。
- 由「分支」节点引出的连线自动成为条件连线（橙色虚线），其余连线为普通连线（灰色实线）。
- 选中节点或连线后按 `Delete` / `Backspace` 可删除（光标停留在输入框内时不会误删）；也可在右侧属性面板点「删除节点」/「删除连线」。
- 画布左上角提供「左右布局」「上下布局」两个按钮：一键按所选方向的分层规则重排节点位置（清空已有坐标后重排），适合节点较多、手工摆放凌乱时使用。
- 画布支持拖拽平移，`Ctrl`（或 `⌘`）+ 滚轮缩放。

**右侧属性面板（参数配置区）**

- 点击画布中的节点或连线，右侧展示对应属性；未选中时提示「请选择节点或连线」。

### 节点属性与参数配置

普通节点（业务节点）在属性面板中可配置：

| 属性 | 说明 |
|------|------|
| 节点编码 | 节点在流程内的唯一标识；首次保存后锁定，不可再修改 |
| 节点名称 | 画布上展示的名称 |
| handler | 该节点执行的业务处理器，下拉可搜索 |
| 最大重试 | 失败后自动重试的次数上限，默认 0（不重试） |
| 重试间隔(秒) | 两次重试之间的等待时间，默认 30 秒 |
| 退避策略 | 「固定间隔」：每次重试等待相同时间；「指数退避」：等待时间逐次翻倍 |
| 超时(ms) | 单次执行的最长耗时，留空表示不限制 |

「开始 / 结束 / 分支」三类系统节点不提供 handler、重试与超时配置，仅按需配置参数（例如开始节点的定时触发配置）。

**节点参数：表单 / JSON 双模式**

- 参数定义由节点 handler 声明。若 handler 声明了参数定义，参数编辑器默认以 **表单模式** 渲染：下拉、数字、开关、日期时间、键值对、JSON 文本等控件按定义生成，并自动填入声明的默认值；声明了「必填 / 取值范围」的参数会在 **保存与发布时统一校验**，不通过则无法保存。
- 表单模式下另有「自由参数」键值区，用于补充 handler 未声明的自定义键；handler 完全未声明参数定义时，整个参数区都是自由键值。
- 切换为 **JSON 模式** 后可直接编辑完整参数 JSON（非法 JSON 不会被写入，保留上次合法值）。

**分支节点的出边条件**

1. 点击分支节点引出的连线，右侧属性面板将「边类型」切换为「条件分支」。
2. 在「whenExpr 表达式」中编辑条件表达式，支持一键插入片段：`${ctx.}`（实例入参）、`${out.}`（上游节点输出）、比较运算符（`==` `!=` `>` `>=` `<` `<=`）、逻辑运算符（`and` `or`）与括号。
3. 表达式编辑器下方可填入「样例 ctx JSON」并点击「试算」，立即预览条件判定结果，避免上线后分支走偏。

条件表达式引用的实例入参以 **发起时填写的入参快照** 为准，实例运行中途修改入参不会影响已在运行的分支判定。

### 内置系统节点

设计器提供四个开箱即用的系统节点，无需业务方额外开发：

| 节点 | 用途 | 说明 |
|------|------|------|
| 开始 | 流程起点 | 把发起实例时的入参原样传给下游；支持配置定时触发（见「实例发起」章节） |
| 结束 | 流程终点 | 标记流程结束，执行到该节点即成功收尾 |
| 分支 | 条件路由 | 对每条出边的条件表达式求值，仅让条件成立的下游链路继续 |
| 定时器 | 等待到点 | 在流程中间插入一段等待：等满指定时长，或等到某个具体时间点后再放行下游 |

定时器节点的等待方式二选一：按等待时长（毫秒，最长一天）或按目标时间点（如 `2026-11-25 08:00:00`）。典型场景如「下单后等待 30 分钟再检查支付状态」。

### 保存与发布

1. 编排完成后点击弹窗底部「**保存草稿**」：内容校验通过后保存为草稿。新建流程首次保存时，后端生成流程编码并创建首个草稿；以已发布版本为底稿打开时，首次保存自动创建新草稿，后续保存覆盖该草稿。
2. 点击弹窗底部的「**发布**」：仅对已保存的草稿可用，从未保存需先「保存草稿」；确认弹窗提示「发布后生成新版本且不可编辑，确认发布？」，发布成功后草稿固化为新版本，流程状态变为「**已发布**」。

**版本语义**

- 已发布版本不可编辑。需要变更时，直接在列表点「**设计**」——系统以最新已发布版本为底稿打开设计器，修改后「**保存草稿**」生成新草稿，「**发布**」即产生新版本号。
- 同一流程同一时刻至多有一个编辑中草稿；历史版本可在「**历史版本**」弹窗中只读回看（流程改名后，历史版本详情中显示的是当前名称）。
- 同一流程可存在多个版本；实例发起时使用的是该流程 **当前已发布** 的版本。

> ⚠ 注意：发布动作会把草稿固化为不可编辑的版本，发布前请通过设计器内的参数校验与分支条件「试算」充分确认编排内容。

## 实例发起

实例 = 某个已发布流程按指定入参运行的一次过程。发起入口在 **实例列表** 页面右上角「发起实例」按钮。

1. 点击「发起实例」，弹出「发起实例」对话框。
2. 「流程编码」下拉框仅列出 **已发布** 的流程（显示为「编码 v版本」），支持搜索。
3. 「traceCode」为业务跟踪编码，可留空，运行期由系统自动回填；填写相同 traceCode 可用于业务层面的唯一性控制。
4. 「参数」以 JSON 形式填写实例入参，例如：

```json
{ "sourceType": "api", "orderNo": "SO20261120001" }
```

5. 点击「确 定」发起实例，成功提示「已发起」，列表自动刷新出现新实例。

**开始节点时间驱动（定时自动发起）**

除了人工发起，开始节点支持按 cron 定时自动发起实例：在设计器中选中开始节点，在参数表单中将触发方式设为 `TIMER` 并填写 cron 表达式即可，例如每天凌晨 2 点触发：

```json
{ "triggerType": "TIMER", "cron": "0 0 2 * * *", "triggerParams": { "bizKey": "value" } }
```

- 设置为 `TIMER` 时 cron 必填，保存与发布时校验其合法性。
- 定时触发对每个触发点自动发起一个实例；系统停机期间错过的历史触发点 **不补触发**，仅补触发最近一个到期时间点。
- 不配置触发方式的流程保持「手动发起」，即通过上述「发起实例」操作触发。

## 实例监控

### 实例列表

**实例列表** 支持按 traceCode（精确）、状态、流程编码（精确）查询。表格展示「实例流水号、traceCode、流程、版本、状态、创建时间、更新时间」，实例状态以彩色标签展示中文文案：

| 状态 | 含义 |
|------|------|
| 运行中 | 实例正在执行 |
| 成功 | 全部节点执行完成 |
| 失败 | 存在节点最终失败，实例终止 |
| 已停止 | 实例被停止 |
| 已终止 | 实例被人工终止 |

操作列提供「**详情**」入口；对「运行中 / 失败」的实例提供「**终止**」按钮（二次确认）。列表本身不做定时刷新，关闭详情弹窗后自动刷新列表。

### 实例详情

点击「详情」进入全屏「实例详情」弹窗，主体为流程画布的只读视图。顶部信息栏展示实例关键信息：

| 信息 | 含义 |
|------|------|
| traceCode | 发起实例时填写的业务跟踪编码，未填写则为空 |
| 流程 | 该实例运行的流程版本（格式：流程编码 v版本） |
| 状态 | 实例五态中文标签（见实例列表章节的状态表） |
| 终止按钮 | 仅「运行中 / 失败」状态可用 |

画布区域：

- 节点按 **执行状态七态配色** 展示：节点本体保留类型配色，右上角圆点与节点第二行文字显示执行状态；画布右上角提供 **状态图例**，颜色与含义一一对应：

| 状态 | 图例文案 | 颜色 |
|------|----------|------|
| PENDING | 待执行 | 灰 |
| RUNNING | 执行中 | 蓝 |
| SUCCESS | 成功 | 绿 |
| FAILED | 失败 | 红 |
| RETRYING | 重试中 | 橙 |
| SKIPPED | 跳过 | 浅灰 |
| MANUAL_STOPPED | 人工停止 | 紫 |

- 实例运行期间详情页每 5 秒自动轮询刷新；实例到达终态后停止轮询，人工干预使实例回到运行态后自动恢复刷新。

### 节点气泡（点击节点）

点击画布中任意节点，弹出 **节点详情气泡**，展示该节点概要：

| 信息 | 含义 |
|------|------|
| 状态 | 当前执行状态，彩色标签展示（七态中文文案见上表） |
| 执行次数 | 已执行的次数与重试上限（格式：`已执行次数 / 重试上限`） |
| 领取者 | 当前领取并执行该节点的调度方；为空表示尚未被领取 |
| 异常 | 最近一次失败的异常信息；无异常显示「-」 |
| 跳过原因 | 仅「跳过」状态节点显示，默认记录「人工跳过」 |

- 气泡下方为 **干预操作按钮**（中断 / 跳过 / 重置 / 重跑，均带二次确认）与「**执行记录**」入口，详见下文「人工干预操作」。
- 点击画布空白处可关闭气泡。

### 执行记录时间线

点击气泡中的「执行记录」，打开「**执行记录 - 节点编码**」弹窗，以时间线展示该节点的完整执行轨迹：

- 每条记录包含发生时间、事件类型（中文标签）、执行方与执行次数（`worker · attempt N`）。
- 事件类型包括：领取、成功、失败、超时、中断、重试已排期、租约回收、跳过、重置、清理、过程日志。
- 「过程日志」记录展示节点执行期间业务代码上报的多行日志原文，是排查节点执行细节的第一手材料；其余事件展示结构化明细。

## 人工干预操作

所有节点级干预操作均位于实例详情的节点气泡中，点击后需二次确认，操作成功后详情立即刷新。各项操作的可用状态已在界面按语义控制，按钮不可用时说明当前状态不满足前置条件。

**操作速查表**

| 操作 | 目标层级 | 可用状态 | 一句话用途 |
|------|----------|----------|------------|
| 中断 | 节点 | 执行中 | 叫停正在执行的节点 |
| 跳过 | 节点 | 待执行 / 失败 / 重试中 / 人工停止 | 不执行该节点，直接放行下游 |
| 重置 | 节点 | 非「执行中」且非「待执行」 | 清除输出与异常，回到待执行 |
| 重跑 | 节点 | 非「执行中」且有历史执行 | 原地再执行一次（先清理后重跑） |
| 从节点重跑 | 实例 | 接口调用 | 从指定节点重建后续执行链路 |
| 终止 | 实例 | 运行中 / 失败 | 一次性叫停全部未完成节点 |

### 中断（interrupt）

- **适用场景**：节点正在执行且执行内容已失去意义（如上游数据被判定作废），希望尽快停下它。
- **前置状态**：节点「执行中」。
- **操作路径**：实例详情 → 点击目标节点 → 气泡「中断」→ 确认「确认中断该节点？」。
- **注意事项**：中断为 **协作式中断**——引擎发出中断信号后，长任务需要节点处理逻辑主动配合（在执行过程中周期性检查中断标记）才会真正停下；不配合检查的任务会执行到自然结束。中断后节点进入「人工停止」状态。

### 跳过（skip）

- **适用场景**：某个节点确认无需执行（如数据已由人工线下处理完毕），希望流程继续往下走。
- **前置状态**：节点「待执行」「失败」「重试中」或「人工停止」。
- **操作路径**：实例详情 → 点击目标节点 → 气泡「跳过」→ 确认「确认跳过该节点？下游将按分支规则继续。」
- **注意事项**：跳过后节点直接进入「跳过」状态并视为完成，**下游节点将以跳过节点的输出继续执行**；跳过原因默认记录为「人工跳过」。若下游分支依赖该节点输出做条件判定，请评估条件取值后再操作。

### 重置（reset）

- **适用场景**：节点已被跳过、停止或失败，需要清除其执行痕迹、恢复到「待执行」等待重新调度（常与后续重跑配合使用）。
- **前置状态**：节点非「执行中」且非「待执行」。
- **操作路径**：实例详情 → 点击目标节点 → 气泡「重置」→ 确认「确认重置为 PENDING？（清除输出与异常）」。
- **注意事项**：重置会 **清除该节点的输出与异常信息**，节点回到「待执行」状态，由调度器重新领取执行。

### 重跑（rerun）

- **适用场景**：节点执行失败或产出错误，修复问题（如修正参数、恢复数据）后原地再跑一次。
- **前置状态**：节点非「执行中」，且该节点 **存在历史执行**（执行次数大于 0）。
- **操作路径**：实例详情 → 点击目标节点 → 气泡「重跑」→ 确认「确认重跑该节点？若有历史执行将先触发清理钩子。」
- **注意事项**：重跑会先触发节点的 **清理钩子**——业务处理逻辑中预留的清理动作，用于清除该节点上次执行产生的业务历史数据，避免重复落库；清理完成后节点重新执行。

### 从节点重跑（rerun-from）

- **适用场景**：流程中某个环节之后的整段链路都需要重新执行（如上游数据修正后，从修正点开始把下游全部重算）。
- **前置状态**：实例存在可定位的节点编码。
- **操作路径**：该能力当前通过接口 `POST /micro-dag/instance/rerun-from`（参数 `instanceCode` + `nodeCode`）调用，界面尚未提供按钮入口。
- **注意事项**：从指定节点重跑会 **重建该节点及其后续的执行链路**，重跑链路中的节点同样遵循清理钩子机制；操作前请确认下游节点具备可重入性（重复执行不会产生脏数据）。

### 终止（terminate）

- **适用场景**：整个实例已无继续运行的价值（如业务单据作废），需要一次性叫停全部未完成节点。
- **前置状态**：实例「运行中」或「失败」。
- **操作路径**：① 实例列表 → 目标实例操作列「终止」→ 确认「确认终止？」；② 实例详情 → 顶部信息栏「终止」→ 确认「确认终止该实例？」。
- **注意事项**：终止为 **实例级操作**，终止后实例进入「已终止」状态，未完成的节点不再调度；已执行产生的业务数据由各节点自身的清理机制与业务逻辑负责，终止不会自动回滚。

## 常见问题 FAQ

**1. 节点一直显示「执行中」，迟迟没有结果？**

先打开节点气泡查看「领取者」是否为空、执行次数是否停滞，再查看执行记录时间线。若执行记录长时间无新事件，可能是执行该节点的服务实例发生了故障：引擎内置 **租约故障转移机制**——每个被执行的节点都持有带时限的租约，租约到期仍无回音时，系统自动回收该任务（时间线会出现「租约回收」事件）并重置为「待执行」重新派给其他服务实例执行，无需人工介入。租约兜底时长默认 120 秒，长任务请与研发确认任务执行时长与租约配置是否匹配。

**2. 分支节点之后的节点全部被「跳过」了？**

分支节点会在上游完成后对每条出边的条件表达式求值，条件不满足的下游链路会被级联「跳过」。全被跳过说明 **没有一条出边的条件成立**：请检查各出边的条件表达式拼写、引用的入参键名（`${ctx.字段名}`）与发起实例时填写的参数 JSON 是否一致——分支判定用的是 **发起时的入参快照**，参数名大小写不一致会导致取不到值。可复制发起参数到设计器的表达式「试算」中验证每条条件的判定结果。

**3. 配置了定时触发（TIMER），到点却没有自动发起实例？**

依次检查：① 开始节点参数中 `triggerType` 是否确为 `TIMER`、cron 表达式是否填写且合法（保存与发布时会校验，但已发布版本的参数无法就地修改，需重新发布新版本——设计时以最新已发布版本为底稿修改参数后保存发布）；② 流程是否处于「已发布」状态——只有已发布版本的定时触发才生效；③ 触发器开关是否被关闭（服务端配置 `dag.trigger.enabled` / `dag.enabled`）；④ 系统停机期间错过的历史触发点 **不补触发**，仅补触发最近一个到期时间点，重启后请关注下个触发周期。

**4. 节点失败后没有自动重试？**

自动重试取决于节点属性配置：「最大重试」为 0 时不重试；配置了重试次数时，失败节点进入「重试中」并按「重试间隔(秒)」与「退避策略」排期重试。请在设计器中确认该节点的重试配置；每次重试都会在执行记录时间线中留下「重试已排期」事件。

**5. 流程图改好了，为什么正在运行的实例没有按新流程执行？**

已发起的实例绑定的是 **发起时那个已发布版本** 的完整快照（节点、连线、坐标都不会变），修改流程不会影响它们。让修改生效的标准动作：列表「设计」（系统以最新已发布版本为底稿打开）→ 修改后「保存草稿」→「发布」→ 新发起的实例即按新版本运行。需要纠偏旧实例时，使用实例详情中的人工干预操作。

**6. 想「跳过」节点但按钮是灰的？**

跳过仅对「待执行 / 失败 / 重试中 / 人工停止」四类状态开放。「执行中」的节点需先「中断」（待其进入「人工停止」后可跳过）；已「成功」的节点视为已完成，不支持跳过。其余干预按钮同理：重置与重跑对「执行中」「待执行」节点不可用，重跑还要求节点存在历史执行。

**7. 重跑节点前系统提示「先触发清理钩子」，这会做什么？**

清理钩子是业务开发在节点处理逻辑中预留的「重跑前清理动作」，用于清除该节点上次执行写入的业务历史数据（如临时表记录、已生成的下游单据），防止重复执行造成数据重复。看到该提示说明引擎会在重新执行前先调用清理动作再跑节点，属正常保护机制；若节点从未执行过（执行次数为 0）则直接执行、不触发清理。
